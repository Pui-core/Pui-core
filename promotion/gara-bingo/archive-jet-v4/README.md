## 今回の音声修正

旧版では発話検索用の時刻補完WAVを最終音源にも使い、発話中へ短い無音が挿入されていました。今回は元アーカイブから発話を直接切り出し、内部の時刻を無音で補完しません。通常の `atempo=1.25` で声の高さを保って速くし、フェードと区間末尾の微小な長さ調整だけを加えます。声は発話ごとに連続した1本として保持し、映像のカットごとには切りません。

元アーカイブのsource時刻と、1.25倍速後の映像内時刻を分け、source区間÷1.25とtimeline区間を30fpsで照合します。字幕・盤面の読了時間は速度変更と別に調整します。架空の本人声・生成ポーズ・表情変更は使いません。盤面の進行は編集上の再構成で、実際の達成順序の完全再現とは扱いません。

音質はASRの成功で判定しません。440Hz音と誤った550Hz処理、旧版の短穴を負例にし、発話の内部無音・波形連続性・末尾処理・最終AACを検査します。曲なし3案のAACも比較します。実施結果は `制作データ/qa/audio-waveform-source-check.json`・`audio-waveform-check.json` と納品検証記録に残します。数値検査と人間の聴感・全編試聴は区別します。

`local-provenance` の旧ASR・時刻補完記録は発話検索の出典です。旧補完WAVを今回の最終音源に使わず、旧ASR結果を音切れ改善PASSへ読み替えません。

## 再編集と再制作

日本語原本はそのまま各編集ソフトで開けます。主要素材は `制作データ/共通素材` と `案別素材/日本語の案名` にあり、配信音声・追加曲・映像マスターを日本語の用途名で区別できます。旧版は保持し、今回の音声修正版は別フォルダへ納品します。

コードで再制作するときだけ、`制作データ/再制作用ファイルを準備.mjs` をWSL Node.jsで実行します。`名前対応表.json` を使い、コード内部のASCII名の作業ファイルを準備します。公開する日本語原本は上書きせず、既存の作業ファイルが変更されていれば停止して保持します。納品時に互換用原本9本を重複コピーしません。

今回の編集設計の正本は `insert-edit.mjs` と生成済みmanifestです。`base-graphics.mjs` の元演出へ `motion.mjs` が差込を加えます。下の再制作手順は同梱の確定manifestを使います。

```sh
cd "納品フォルダ/制作データ"
node "再制作用ファイルを準備.mjs"
export OSAYU_ARCHIVE_ROOT="$PWD"
cd "制作ソース"
node pipeline.mjs prepare
node pipeline.mjs previews
node audit.mjs "$OSAYU_ARCHIVE_ROOT"
node pipeline.mjs render
node pipeline.mjs verify
```

Windows版EffectCraft/FilmCraft/FFmpeg/FFprobe/ImageMagickとWSL Node.jsが必要です。数値音声検査にはPythonとNumPy/SciPyが必要です。選択済み素材でのprepare/renderは元動画全体や旧補完WAVへ依存しません。元から抽出し直す場合・独立した元音声の検査には元動画が必要です。元動画全体と長い解析WAVは同梱しません。

再梱包には現在のmain/preview SHAの目視記録、現在の発話・最終AAC波形検査、6動画の技術検査が必要です。新しい検品結果へ更新し、元フォルダと重ならない納品先を指定します。

```sh
node package.mjs /mnt/f/Users/pui/Documents/gara/ビンゴ達成ありがとう_再出力
```

素材・試聴・人物入り動画は公開Gitへ入れず、SNS投稿も行いません。人間による全編試聴、TikTok実機、ownerの創作上の採用は別に記録します。
