# おさゆ A案・予告からつながるループ版

A案「倍倍FIGHT!」を、本人の歌投稿予告から始まる構成にしています。ビンゴ企画の達成と感謝を見せ、最後にごほうびの理由を置き、本人の「でもね、これ全部埋まったらね」という声から冒頭の予告へつなぎます。B・C案と前の納品版は保持します。

1周は約24.533秒・736フレーム、9:16です。本人が話す6区間は、その声と元動画の時刻が一致する配信映像をフレーズ全体に表示します。間は淡い紙背景・ビンゴ盤面・文字・元の立ち絵の全画面演出でつなぎ、発話中に画面を覆うワイプを入れません。配信映像と本人の声はピッチを保つ1.25倍速、追加曲は通常速度です。正本は `制作データ/edit-manifest.json` です。

## まず開くもの

`A案をループ再生する.html` は曲入り版を繰り返し再生できます。次の3本を日本語名で同梱します。

- `A案_倍倍FIGHT_ループ版_切り抜き1.25倍_曲入り確認用.mp4`：配信音声と公開試聴曲を合わせた私用確認版。
- `A案_倍倍FIGHT_ループ版_切り抜き1.25倍_配信音声のみ.mp4`：配信音声版・追加BGMなし。TikTokで曲を後付けする版。
- `A案_倍倍FIGHT_ループ2周確認用.mp4`：実際に2周をつないだ約49.067秒・1472フレームの確認版。中央の継ぎ目を確認できます。

HTMLのループにはプレーヤーの都合で間が入る場合があるため、素材そのものの継ぎ目は2周確認用でも確認します。「配信音声のみ」には元配信のBGMやギフトSEが残る場合があり、純粋なボーカル分離音源ではありません。投稿用の合わせ方は [音源後付けガイド](音源後付けガイド.md) を参照してください。

編集原本3本は `編集原本/A案_倍倍FIGHT/` にあります。

| 原本名の末尾 | 用途 |
|---|---|
| 映像編集.ecproj | EffectCraftの本番映像 |
| 人物未読込確認.ecproj | 人物画像・配信動画をimportしない確認原本 |
| 映像と音声編集.fcproj | FilmCraft。V1=映像、A1=配信音声、A2=追加曲 |

## ループの声・映像・曲

末尾の条件の声と冒頭の歌投稿予告は、元配信で連続する1つの発話です。元アーカイブからまとめて直接切り出し、1回の `atempo=1.25` 処理後にサンプル単位で分けて末尾と冒頭へ配置します。ループ境界で声を別々に引き伸ばしたり、発話内部へ時刻補完の無音を挿入したりしません。

末尾の配信映像のsource終端を、冒頭映像のsource起点へつなぎます。全体カメラは冒頭・最終表示フレーム・終端で同じ値に戻し、予告の字幕とヘッダーも同じ表示にします。人物の画像内容・local基準値は変えません。

曲は0秒から、発話に連動して下げず固定ゲインで流します。曲自体の強弱は保ちます。曲の末尾0.15秒だけ、冒頭直前の曲区間へつながるように混ぜる処理を許可し、それ以外の自動音量変化は入れません。最終ミックスも固定倍率で加算します。

音質はASRの成功で判定しません。短い無音穴・波形連続性・ピッチと最終AACを検査し、旧版の短穴と誤ったピッチ処理を負例にします。固定音楽ゲインの検査に加え、末尾の宣言済み処理を独立して再現し、音楽と声のループ境界、実際の2周確認用AACを検査します。数値検査と人間の全編試聴は区別します。

結果は `制作データ/qa/audio-waveform-source-check.json`、`audio-waveform-check.json`、`music-check.json`、ループ音声検査と納品検証記録に保存します。`local-provenance` の旧ASR・時刻補完記録は発話検索の出典であり、今回の音質PASSへ読み替えません。

## 再編集と再制作

日本語原本はそのまま編集ソフトで開けます。主要素材は `制作データ/共通素材` と `案別素材/A案_倍倍FIGHT` にあり、切り抜き・発話・処理前の音声も日本語の用途名で区別できます。旧版は保持し、別フォルダへ納品します。

コードで再制作するときだけ、`制作データ/再制作用ファイルを準備.mjs` をWSL Node.jsで実行します。`名前対応表.json` を使ってASCII名の作業ファイルを準備します。公開する日本語原本は上書きせず、既存の作業ファイルが変更されていれば停止して保持します。互換用の原本3本を納品時に重複コピーしません。

編集設計の正本は `insert-edit.mjs` と生成済みmanifestです。`base-graphics.mjs` の元演出へ `motion.mjs` が編集を加えます。次の手順は同梱の確定manifestを使います。

```sh
cd "納品フォルダ/制作データ"
node "再制作用ファイルを準備.mjs"
export OSAYU_ARCHIVE_ROOT="$PWD"
cd "制作ソース"
node pipeline.mjs prepare
node pipeline.mjs previews
node audit.mjs "$OSAYU_ARCHIVE_ROOT"
node pipeline.mjs render
node pipeline.mjs loop-check
node pipeline.mjs verify
```

Windows版EffectCraft/FilmCraft/FFmpeg/FFprobe/ImageMagickとWSL Node.jsが必要です。数値音声検査にはPythonとNumPy/SciPyが必要です。選択済み素材でのprepare/renderは元動画全体や旧補完WAVへ依存しません。元からの抽出・独立した元音声検査には元動画が必要です。元動画全体と長い検索用WAVは同梱しません。

再梱包には現原本SHAの目視記録、現6発話・最終2動画・2周確認用の音声検査、固定音楽ゲインとループ接続の検査、動画3本の技術検査が必要です。旧版のPASSは流用せず、新しい検品結果へ更新してから元フォルダと重ならない納品先を指定します。

```sh
node package.mjs /mnt/f/Users/pui/Documents/gara/ビンゴ達成ありがとう_A案ループ_再出力
```

素材・試聴・人物入り動画は公開Gitへ入れず、SNS投稿も行いません。人間の全編試聴、TikTok実機、ownerの創作上の採用は別に記録します。
