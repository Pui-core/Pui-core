# 音桜夢（おさゆ）初ビンゴ・動画試作

タスク正本：[運用Issue #83](https://github.com/Pui-core/-/issues/83)。元投稿：[TikTok写真投稿](https://www.tiktok.com/@oosayuuu2525/photo/7699907163560447233)。開催日時はownerが会話で **11/24 22:00** と確認済み。

## 決定した方向性

**「初見もひと言から参加できる、一緒に目標を進めるVライバー」**として見せる。今回確認できた写真投稿では、ビンゴとX開設の告知が同居し、装飾の多い盤面に9目標とご褒美が並ぶ。動画では最初に「一列達成でリクエストセリフ」という見る理由を伝え、参加の入口を「初見さん」「おはさゆ」に絞ってから盤面全体を見せる。最後はTikTok配信への案内だけにする。

この判断は、立ち絵と今回の写真2枚・本文を基にした仮説。全投稿の比較やTikTok Analyticsの確認はできておらず、アカウント全体の再生傾向・視聴者属性を分析済みとは扱わない。

## 今回の動画

22秒、1080×1920、30fps、H.264/AAC。字幕主体のモーショングラフィックスで、本人音声は未提供のため使用していない。背景と透過立ち絵は組み込みimagegen、動きと文字・盤面はEffectCraft 0.14.0、映像とオリジナル音楽の編集・出力はFilmCraft 0.10.0で制作。

| 時間 | 映像・伝える内容 |
| --- | --- |
| 0〜3秒 | キャラクターの寄り。「一列そろったら、好きなセリフ、言います。」 |
| 3〜7秒 | 「おさゆ、ビンゴ初挑戦。」初見への招待 |
| 7〜12秒 | 初見さん20人・おはさゆ20回の目標を拡大。ひと言から参加できることを伝える |
| 12〜17秒 | 9マスとご褒美を正確に表示。架空の達成・進捗は加えない |
| 17〜22秒 | 11/24 22:00、TikTok LIVE、プロフィールから配信へ |

全マス達成のご褒美は**歌ってみたのサビを後日投稿**。「1曲投稿」に拡張しない。一列ごとのセリフ報酬、9マスの数字も元画像どおり。

## 次の投稿への展開

告知だけを続けず、「セリフや歌の実際の短い切り抜き」「視聴者と進める企画」「達成や配信後の反応」の3系統で継続する。本人の声を使える次回は、冒頭1〜2秒に実際のセリフや反応を置く。数字の保証や、実際に起きていない盛り上がりの演出は行わない。

効果は同程度の尺・投稿経過時間の既存投稿と比べて、冒頭離脱、平均視聴時間、完視聴、プロフィール閲覧、LIVE流入を確認する。主な目的は再生だけでなく**配信への流入と初見の参加**。今回の制作だけで効果が確認されたとは扱わない。

## 編集と再生成

メディア正本は `/home/pui/Videos/Osayu-Bingo/2026-10-24/`。`projects/` に `.ecproj` と `.fcproj`、`media/` に立ち絵・背景・BGM・無音マスター、`source/` に生成したJSX、`qa/` に文字実測・5場面の静止画・出力検査を保存する。私有立ち絵や完成メディアはGitHubへアップロードしない。コードと制作仕様をPRで管理する。

```bash
node audio.mjs /home/pui/Videos/Osayu-Bingo/2026-10-24
node produce.mjs prepare
node produce.mjs previews
node produce.mjs render
node produce.mjs verify
```

`OSAYU_BINGO_ROOT` で作業先を変えられる。入力素材 `media/character-cutout.png` と `media/stage-background.png` が必要。WindowsネイティブCLIが参照できる `wslpath -w` のパスを保存する。別PCへ渡す際は原本の素材を再リンクする。

既存GUIや他担当のプロジェクトを操作せず、独立CLIプロセスで保存・再読込する。`prepare` の再実行時は旧EffectCraft原本を `checkpoints/` に保存する。

## 検品の範囲

文字57レイヤーをネイティブで実測し、x=94〜897、y=210〜1530内に配置。最小文字20px、主要見出しは59〜112px。重要情報は右側と下部のTikTok UIから離している。配置は実機のアプリ表示やキャプション量によって変わる。

EffectCraftの5場面を目視し、顔へのカード重なりと日時の詰まりを修正。元盤面との原稿対照を別の補助エージェントでも実施したが、独立したGitHub PR承認とは扱わない。最終メディアの検査結果は納品先 `qa/` が正本。全編の人間による実時間視聴・試聴は未実施。
