# 7日で何を試し、どう配分を変えるか

## 今回の実行

10/26〜11/1を、別エピソード3本/日の探索期間にします。ownerの投稿上限はありません。3本は最初の配分で、恒久上限でも最適解の証明でもありません。技術自慢・支援告知の前に、実際に見て面白い変化を一つ置きます。

| 10/26 | game #97・計画 | app #100・計画 | MIX #99・既予約 |
| 10/27 | appの別の実話 | musicの別の実話 | gameの別の実話 |
| 10/28 | musicの別の実話 | gameの別の実話 | appの別の実話 |
| 10/29 | gameの別の実話 | appの別の実話 | musicの別の実話 |
| 10/30 | appの別の実話 | musicの別の実話 | gameの別の実話 |
| 10/31 | musicの別の実話 | gameの別の実話 | appの別の実話 |
| 11/1 | gameの別の実話 | appの別の実話 | musicの別の実話 |

題材と時刻を完全固定しないための回転です。時刻の最適性や3本の因果を識別する比較実験ではありません。2日目以降の実話・素材はまだ確定しておらず、架空の活動を計画表から発生させません。実素材・品質が足りない枠は欠測/未投稿として残し、本数のための投稿をしません。新しいowner指示や明確な反応が来れば計画を更新します。

## 測定

1. 各公開IDと動画SHAを結び、実公開時刻から24h/72hのdueを付けます。予約段階に公開成績を付けません。複数投稿はそれぞれ別のreceipt・dueを持ちます。
2. 最優先は同じJST日内のaccountフォロワー純増です。毎日の開始/終了人数と観測時刻を記録し、増えた総数だけでなく解除も含む純増を使います。
3. 投稿別の新規フォロー/1000視聴は、nativeに同じ範囲の投稿別項目がある場合のみ。無ければnullです。account日次を投稿へ割り振りません。プロフィール遷移も同じです。
4. 平均視聴時間・完視聴・保存・共有・コメントを同じ公開後年齢で見ます。異なる尺・題材の完視聴率を一列に並べて優劣を決めません。0分母/未提供/処理中は評価null。表示0は観測値として別欄に残します。
5. 同じ題材・近い尺・同じ経過時間の複数の別エピソードで、中央値と範囲、分母、欠測を併記します。1本の大当たりや失敗で勝ち筋を決めず、保存/共有などは補助にします。

各テンプレート：[投稿単位](./data/post-observation-template.json)・[account日次](./data/account-day-template.json)。語頭語尾・実素材・指定モデル・画面・音の品質確認は投稿数に関係なく維持します。

## 7日後の判断

11/2 20:00 JSTに全21枠の24h側を整理し、11/4 20:00に72h側を補完します。最終日の実公開が遅れた分はdueも後ろへずらします。未投稿は未投稿、処理中は欠測です。

- **露出が全作0/処理中のまま**：公開ID/範囲・実公開・処理/推薦資格の通知を先に点検。0再生からフックの敗北やシャドバンを断定しません。データ不足を無期限の全作業停止ゲートにもせず、調査・良い実話の準備を続けます。
- **見られたがフォローへつながらない**：同題材で冒頭と、固有の次回予告のどちらを変えるか一つ決め、別の実話で検証します。フォロー項目が無ければaccount日次の代理値と明示します。
- **複数の近い投稿で純増/率が良く品質を保つ**：次週を暫定60%同じ核の新しい実話、30%近い変化、10%新規へ配分。21枠なら13/6/2程度で、数学的な最適配分ではありません。判断材料が少なければ探索を延長します。
- **本数を増やすか**：日ごとの純増の中央値、近い尺・題材の投稿別率（取得時だけ）、品質欠陥・制作余力を合わせて判断。品質を保ち、純増が繰り返し良い場合に次週の一部の日だけ4本を試し、全日に即拡大しません。品質やフォロー率が落ちたら量より内容を修正します。

比較群のない最初の週から「3本/日のおかげ」と断定できません。外部露出・題材・時間・曜日などの交絡が残ります。再現できる切り口を増やすための探索です。
