# 履歴詳細を収録するための保全と有限手順

録画手順とbatch-controlは **準備のみ・未実行**。初版作成後、Rootが許可したcold読取・新私有退避の限定試行を1回行ったが、端末一覧の読取25秒timeoutで停止した。app-data読取/backup/展開は0、boot/GUI/録画/install/shutdown/旧書込も0。4つのRuby補助はMac構文検査のみ成功した。[限定試行の原票要約](cold-attempt-result.json)を参照。旧121の過去のShutdown/Issue CLOSEDを現在の利用権限へ一般化せず、次のMac進行はRootが案内する同じ有限窓の範囲で扱う。ownerへ新しい確認を求める工程は追加しない。

第一案は **既存アプリ＋RootのTigerVNC通常操作＋指定UDIDのrecordVideo**。XCTest/旧caller/Runnerを実行しない。`test-without-building` もUI Runnerの配置を伴い得るため、install行を削っただけでinstall0としない。AppleはUIテストが別のRunner app内で動くと説明している。[Apple Xcode Help](https://help.apple.com/xcode/mac/current/en.lproj/dev6061748b5.html)

## 1. 有限窓前半：新鮮な状態とcold退避

1. Rootが対象UDIDの排他利用・MacのGUI窓・他担当予定を確認し、window ID/担当者/開始・終了時刻を記録。別UDIDは稼働していてよい。そのUDID/PID/所有者を記録し、入力・停止の対象から除く。
2. `xcrun simctl list devices --json` の新しい原票、対象device.plistのstate/name/runtime、対象UDID/旧rootに関係する録画・xcodebuild・Runner等のPID/PPID/UID/起動時刻/引数を私有出力へ保存。**対象が既にBooted、使用者不明、関連consumerありならbootせず保留**。他者が起動した端末を今回の自起動へ読み替えない。
3. `simctl get_app_container`の過去の値だけに依存せず、対象device配下のcontainer metadata/Info.plistでbundle IDと実app-data/app-bundleを同定。既知パスとbinary SHAを照合。container UUIDはまだ未確定で、推測しない。
4. 対象Shutdownのまま、新rootの`backup/`へapp-data全体をネイティブ`ditto`等で冷退避する。原本はコピー元のみ。選択したCLIのローカルman/引数を確認して1回だけ有限実行。アーカイブを作っただけで保全完了にしない。
5. 例として`ditto -c -k --sequesterRsrc --keepParent <確認済app-data> <新backup.zip>`、別の新規`verify-extract/`へ`ditto -x -k`で展開する案を用意した。**このコマンド・xattr/ACL保持・展開はMacで未実行**。data fork/リンク/モードは`cold-manifest-prepared.rb`の入力側と展開側で同じ相対一覧/SHAにする。xattr/ACLはネイティブarchiveの別証跡を残す。元app-dataは再読して、退避中に変わっていないことも確認する。
6. `device.plist`、旧harness3、installed binaryのコピー/SHAとbefore原票を保持。archive SHA、元/展開先のfileListSha256、不一致0、保存キーData SHA・件数・id群SHAを`backup/verified-manifest.json`へまとめる。コピー/展開/再hashに失敗・timeoutしたらbootせずHOLD。同じ失敗を反復しない。
7. preferencesを**コピーから**`plutil -convert xml1 -o <新preferences.xml>`とし、`history-data-inspect-prepared.rb`へ渡す。正確な`gameHistory.records`のData bytes SHAを取得。AA/BB・4Rだけの候補を私有票へ出し、他のrecord本文は出力しない。UI件数だけではLossy decodeで落ちた項目を検出できないので、Data SHA/record IDsと併用する。
8. 4つのRuby補助とshellのnative構文・依存をこの段階で確認。WSLにはrubyが無い。後続の限定Mac試行では4ファイルのRuby構文だけ成功し、Data parse/archive/helper実動作は未検証。Macで`/usr/bin/ruby -c`に失敗してもインストールや補修を始めず、保全した状態でRootへ返す。

cold退避/検証時間は素材尺に数えない。app-data/Root窓/別UDID状態の生情報は私有原票に置き、Gitへ個人データを転載しない。

## 2. 同じ有限窓：外側batchと通常UI

`batch-control-prepared.sh`はRootの`root-window.json`とverified-manifestの実SHAが揃わない限り拒否する。`window.template.json`はfalse/nullの準備票で、使用許可ではない。Root窓の期限は最大15分、録画は30〜180秒の有限設定。Rootが確認済みの値だけを記入する。新Root窓ID/新outputで、過去のCLOSEDを利用許可へ一般化しない。

外側処理はboot要求前にEXIT/HUP/TERM/INTのfinallyを設定し、同じバッチ全体の1台/1録画を管理する。RootがSSH断後も終端票を取得できる起動方法を用い、SSH接続そのものを持続の条件にしない。録画外側コードは未実行で、まずnative前半確認を通す。各bounded段階には期限を設けるが、直接cp/補助ps等まで含む厳密な全体上限は未検証。今後の実行には、起動時のPID/UID/birth/引数を結ぶ外側監視を置き、上限超過時も自己PID照合→TERM→終端確認まで行う。今回のcold限定試行は46秒で終端しており、600秒の目標を超えていない。

1. batchは全UDID状態と対象consumerを再取得。対象Shutdownを確認後、boot要求を永続記録。`simctl boot <対象>`が成功した場合だけ自起動acceptedを記録し、bootstatusは1回/最大120秒。
2. 要求timeout後にBootedとなっても、要求票だけで所有確定としない。対象を削除/clone/再bootせずRoot照合へ。所有不明のままshutdownしない。
3. 指定UDIDのnative screenshotを`batch/target-before-ui.png`へ取得し、そのSHAを保存。RootがTigerVNCの**ProjectP121 TruthOrLie Captureという対象窓**と画像を照合する。別UDIDが前面なら、Rootが対象窓を選択し直す。`recording.READY`だけで最初のタップをしない。
4. Rootは入力前に同じwindow ID/UDID/対象窓名/screenshot SHA/確認時刻を`root-target-window-confirmed.json`へ記録。これは同一窓の対象照合証跡で、ownerの別承認ではない。
5. recorderは`simctl io <対象UDID> recordVideo --codec=h264 --mask=ignored <新.mov>`。PID/PPID/UID/起動時刻/固有の出力パスを記録し、Recording startedを有限待ち。起動失敗時に空movを成功としない。
6. Rootは既存TruthOrLieのアイコン/通常UIから開く。保存データを注入せず、新ゲーム・設定変更・履歴の削除を行わない。対象アプリ画面をnative screenshotと照合できない場合は入力を止める。
7. 一覧の**AA/BB・4R・引き分け・実日時**を同定。候補が複数ならcold票の日時/id対応を確認し、似た別recordを開いて成功にしない。実4Rの最終はAA2/BB2で、別の真実のみ3Rの1対2と混ぜない。
8. 通常NavigationLinkで対戦詳細へ。`対戦詳細`/`最終スコア`とAA2/BB2を確認。`ラウンド履歴`へ寄り、R1を押して展開。実際の「初めて自分のお金で買ったもの／赤い自転車」、嘘/投票、出題AA/推理BBを確認する。存在しない場合はunknownとして原票を残し、設定や回答を作り直さない。
9. 必要なら同じrecordの別roundを短く確認。スクロール待機を作品尺にせず、原録画は連続保持。ラウンドごとに端末を止めない。
10. Rootが入力を終え、同じwindow ID/UDIDに対する他利用を確認して`root-ui-released`へJSONを保存。issuer/Root窓ID/UDID/現在epoch/rootInputFinished/otherTargetUsersChecked/otherTargetUsersPresent=falseを含める。終了時の記録は90秒以内のものだけを使う。空markerや古いファイルだけで他利用なしとしない。

## 3. finallyと後片付け

1. 自分の実行PIDだけをPPID/UID/起動時刻/引数で照合して終了。recordVideoはSIGINT→最大30秒wait。PID再利用・所有不明・残存なら一括killへ進まずHOLD。録画exit非0も検品失敗として保持するが、録画プロセスが終端済みで他利用が無い場合の自己端末cleanupとは区別する。
2. 全ケースのRoot入力と自分の録画/commandを終えた後、Rootの新しいrelease記録＋対象関連consumerを再確認。Rootがまだ対象を使う、別consumerがいる、確認が失敗ならshutdownしない。自起動accepted/所有が確定し、他利用がない対象だけ`simctl shutdown <6FC6…>`を1回有限実行。
3. target device.plist state1と、新しい`simctl list devices --json`の対象Shutdownを両方保存。別UDIDは操作しない。状態変化があれば記録するだけで、他者のboot/shutdownを勝手に戻さない。
4. Shutdown後にapp-data/preferencesをもう一度冷読し、`gameHistory.records`のData SHA/record IDs/件数と旧harness/binary SHAをbeforeへ照合。app-data全体の差分も記録。端末OSメタデータ変化を保存データ不変と混同しない。
5. 原movのffprobe/全decode、実frameと正しいrecordの照合、raw/SHA/全終端票まで揃えて初めて収録バッチを完了にする。補助bashは常に`complete=0 until Root verifies state/data/MP4`と残す。成功exitだけで完了としない。

`shutdown all`、`killall`/`pkill`、共有CoreSimulatorサービス停止、Simulator.app全体の終了、対象device/app削除・erase・旧Runner再installは実行しない。

## 4. 失敗別の復旧

| 失敗 | 続ける範囲／止める範囲 |
| --- | --- |
| cold archive/SHA/キーのdecode失敗 | bootせず、新backupと原票を保持。同一再試行・修復0 |
| boot要求timeout/SSH断 | 永続boot-request/boot-owned/command PID票と対象現在stateをRootが照合。accepted不明なら自起動と決め付けない |
| GUI対象を照合できない | 入力0またはその時点で停止。rawを保持し、Rootが正しい窓を同定。別UDIDの停止で解決しない |
| record/test consumerの所有不明・PID再利用・残存 | シグナルを送らずHOLD。録画・端末のcleanup未完を具体的に報告。全体完了0 |
| Root入力/他利用の終了不明 | 自分の録画が止まっても対象shutdownを保留。Root窓内で現利用を再確認する |
| 原mov破損・必要UIなし | 素材成功0。cleanupは独立して実施/確認。同じ旧harnessのinstall・録画を反復しない |
| 保存Dataが変化/欠落 | after原本も別に冷退避し、不一致を固定。自動restore/clear/reinstallをしない。Rootが不一致理由を調べてから、対象Shutdown/他利用0の保守窓で復旧手段を決める |
| shutdown/再確認失敗 | 自起動端末のcleanup未完を報告。共有サービス/他UDIDは触れず、保持lock/実PID/状態をRootへ渡す |

復旧を行う場合も退避済み原本を上書きしない。まず**新しい検証用dirへの展開**でData SHAがbeforeへ戻ることを確認。元containerへの書き戻しはこの閲覧収録の自動範囲へ含めず、Rootの原因別保守判断とする。cold退避の保存データ復旧点と、端末全体を元のOS状態へ戻す保証は別である。

## 5. 編集への受け渡し

現269.653秒/8089f/SHA294b9cc6…f539d1と旧203秒は保持。本収録は成功して初めて既6章の第6章へ結ぶ。「2対2で終わったあと、何を見返せる？」→実一覧の正しい1件→実詳細の同じ最終点→R1の赤い自転車と嘘/投票→旧R1結果との照合、という新しい問い/観測として扱う。元UI全画面を小さく長く置かず、record同定・結果・回答の見せ場へ寄る。尺は観測後の実有声/必要読取から決める。

旧setupの2〜10人/名前入力/4R・195問summaryは既素材の短い導線比較候補として保持。新しい保存再適用や履歴詳細の成功に数えない。現時点で追加動画秒数0、正式600秒まで330.3667秒不足のまま。履歴収録ができれば残秒を全て満たすという計画は立てない。
